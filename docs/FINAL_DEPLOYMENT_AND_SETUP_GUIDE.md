## 1. Prerequisites & Environment Setup

### System Requirements
- **Operating System:** Windows 10/11 64-bit or Ubuntu Linux 22.04+ LTS.
- **Docker Engine:** Docker Desktop v4.28+ with WSL2 Linux backend enabled.
- **Memory:** Minimum 8 GB RAM (16 GB recommended).
- **Storage:** Minimum 10 GB free disk space.
- **Network Ports:**
  - `5175`: Docker Frontend UI
  - `8001`: Docker Gateway API
  - `8000`: Standalone Windows Executable Dashboard & API
  - `5432`: Docker Hybrid-Lab PostgreSQL
  - `5434`: Standalone Executable Dedicated PostgreSQL

## 2. Demonstration Mode 1: Docker Hybrid-Lab Environment (Recommended)

This mode runs the complete 13-container hybrid cloud network simulation with active routing and traffic generation.

### Step 1 — Ensure Docker Desktop is Active
Verify the Docker daemon is responding:
```powershell
docker ps
```

### Step 2 — Start the Hybrid Lab Fleet
From the project workspace root, start the fleet in detached mode:
```powershell
docker compose -f deployment/hybrid-lab/compose.yaml up -d
```
Verify that all 13 containers report `Up (healthy)`:
```powershell
docker compose -f deployment/hybrid-lab/compose.yaml ps
```

### Step 3 — Open the Security Operations Dashboard
Open your web browser and navigate to:
**`http://localhost:5175`**

### Step 4 — Log In with Administrative Credentials
- **Username / Email:** `<ADMIN_EMAIL>` (e.g., configured administrator account)
- **Password:** `<ADMIN_PASSWORD>` (configured during deployment)
- The system issues a secure JWT access token and sets an HttpOnly refresh cookie.

### Step 5 — Inspect Ingested Security Events
- Navigate to **Security Events** from the left navigation sidebar.
- Inspect the 4,729 deduplicated network flow events persisted in PostgreSQL.
- Review flow classifications: `BENIGN`, `PORT_SCAN`, `TRAFFIC_SPIKE`, `SUSPICIOUS_TRANSFER`, and `BRUTE_FORCE`.

### Step 6 — Review ML Threat Predictions & SHAP Explanations
- Select any event to open the **Flow Investigation Modal**.
- Verify that the active model is **Big Data XGBoost V2** (`candidate_xgboost_v2`).
- Inspect the SHAP feature attribution bar chart:
  - Port scans highlight elevated `unique_dst_ports`.
  - Brute-force attacks highlight `dst_port: 22` and high `packet_count`.
  - Exfiltration highlights high `bytes_per_sec` and `byte_count`.

### Step 7 — Run Attack Simulation Scenarios
- Navigate to **Attack Simulation** from the left navigation sidebar.
- Locate the six scenario cards:
  1. **Benign HTTP Traffic:** Standard user web browsing emulation.
  2. **Port Scan:** Multi-port reconnaissance targeting cloud subnets.
  3. **Traffic Spike:** Volumetric throughput burst.
  4. **Suspicious Transfer:** High-volume base64 exfiltration.
  5. **Containment Verification:** Simulated perimeter isolation test.
  6. **SSH Brute-Force:** Multi-credential authentication attack.
- Click **Launch Scenario** on Card 6 (Brute Force) or any individual card.
- Watch the progress indicator transition through `QUEUED` $\to$ `RUNNING` $\to$ `COMPLETED`.
- Observe the updated PCAP trace registered in the execution history table.

### Step 8 — Demonstrate DRY_RUN Policy Containment
- Navigate to **Policies** in the sidebar.
- Review the dynamically generated firewall recommendations generated by the risk engine.
- Note the `[DRY_RUN]` indicator on every policy.
- Accept a proposed policy rule.
- Verify in `lab-router` that zero destructive rules were installed in the live Linux kernel:
  ```powershell
  docker compose -f deployment/hybrid-lab/compose.yaml exec lab-router iptables -L -n -v
  ```

### Step 9 — Safe Shutdown (Preserving Volumes & Data)
When the demonstration is concluded, shut down the containers **without deleting volumes**:
```powershell
docker compose -f deployment/hybrid-lab/compose.yaml stop
```
> [!CAUTION]
> NEVER run `docker compose down -v` or `docker system prune`, as this will destroy the persistent PostgreSQL database and telemetry PCAP volumes.

## 3. Demonstration Mode 2: Standalone Windows Executable

The standalone executable packages the backend API, the compiled React frontend (`dist/`), and the bundled machine learning models into a single portable binary.

### Step 1 — Ensure Database Container is Active
The standalone executable connects to PostgreSQL on port 5434:
```powershell
docker ps --filter "name=gateway-postgres"
```
*(If stopped, start it via `docker start gateway-postgres`).*

### Step 2 — Launch the Standalone Executable
Execute the compiled binary from PowerShell:
```powershell
& "backend\executable\AdaptiveSecurityGateway\AdaptiveSecurityGateway.exe"
```
Startup log output will confirm:
```text
Adaptive AI Hybrid Security Gateway API v1.0.0
Authoritative Production Model: candidate_xgboost_v2 (Big Data XGBoost V2)
Standby Rollback Model: production_rf (Random Forest Baseline)
Uvicorn running on http://127.0.0.1:8000
```

### Step 3 — Open the Standalone Dashboard
Open your browser and navigate to:
**`http://localhost:8000`**

### Step 4 — Standalone vs. Docker Hybrid-Lab Comparison
| Feature | Docker Hybrid Lab (`:5175`) | Standalone EXE (`:8000`) |
|---|---|---|
| **Frontend Server** | Docker Nginx container | Embedded in Python binary |
| **Backend API** | Docker container (`:8001`) | Native Windows process (`:8000`) |
| **Scenario Execution** | Live IPC trigger daemon in Docker | Read-only simulation viewer |
| **Network Routing** | Multi-subnet Linux bridge (`lab-router`) | Host loopback emulation |
| **Telemetry Sensor** | Live Scapy sniffer in Docker | Local sample PCAP playback |
| **ML Inference** | Active XGBoost V2 | Active XGBoost V2 |
